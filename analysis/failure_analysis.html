The headline

Both pipelines score the same, fail on the same 10 gold variants, and lose most of their score in the same place. But the agentic run was handed 6 of its 10 missed variants by its own tool and threw them away.

The buried lever

The agentic pipeline called extract_variants on all 16 papers. On 2 of them the tool returned gold variants the model then dropped from its answer: the three copy-number alleles CYP2D6*1xN / *2xN / *4xN (PMC6435416) and three HLA alleles HLA-B*35:01 / HLA-C*04:01 / HLA-DRB1*01:01 (PMC3387531).

Simply unioning the regex candidates into the output keys lifts val coverage from 0.888 → 0.955 at zero API cost. The cause is a line I wrote in the agent's own workflow prompt: “ignore what it found that the paper does not really discuss.” The model obeyed.

Where the score goes

Each of the 101 gold sentences is scored 0–1 by the diagnostic judge. Bucketed: captured ≥ 0.75, partial 0.25–0.75, lost < 0.25. Roughly half of all gold meaning is never recovered, and only a fifth of that loss is a missing variant.

The dominant failure is not extraction. It is writing the sentence correctly once the variant is already found: gold sentences land in QUALIFIER_DROPPED and in SENTENCE_LOST, against only lost to a missing variant. Every tool built so far — the regex extractor, the term lookup — targets the smallest of those three buckets.

Three root causes

1. The prompt forbids the answer (n=3 sentences, capture 0.000)

PMC10880264's gold keys include CYP2C19 intermediate metabolizer and CYP2D6 poor metabolizer — metabolizer phenotypes used as variant keys. The champion prompt, inherited verbatim by the agentic run, says:

…NOT metabolizer labels ("PM/IM", "poor metabolizer"); translate to the underlying alleles/diplotypes…

Both pipelines obey and both score 0.000 on all three of that paper's gold sentences. The rule is right for most papers and catastrophically wrong for this one. It is a prompt bug, not a model failure — and it is the only failure class here with a guaranteed fix.

2. Copy-number and HLA alleles: found, then discarded (n=6 variants)

extract_all_variants() returns CYP2D6*4xN and the full HLA set. The model dropped them. Note the trap for anyone reusing that module: its sibling normalize_star_allele() strips the xN suffix (CYP2D6*4xN → CYP2D6*4), which would silently destroy these keys if wired into the output path. The extractor is fine; the normalizer is not.

3. Qualifier loss is the real ceiling (n≈30 sentences)

The judge awards partial credit when “the core association is captured but an important qualifier, population, comparison, or genotype detail is missing.” This is the single largest bucket in both pipelines and no lever tried across jun4, jun5, or jul9 — framing rules, few-shot, ensembling, extended thinking, agentic tools — has moved it. It is untouched territory.

What the agent actually changed

MetricChampionAgenticReading

The agent is a strictly more precise pipeline — it emits fewer keys and fewer sentences, and coverage is unchanged, so everything it dropped was spurious. eval.py scores recall only and does not penalize extra predictions, so precision is invisible to the metric and surfaces purely as cost: ~$6.30 and ~12 min per run against ~$0.02 and 56 s.
