agentic 0.541/0.888 similar — claude-agent-sdk loop + 4 tools (search_paper, extract_variants, lookup_term, submit_annotations). 3 runs: 0.541/0.531/0.551, sd 0.008. Coverage IDENTICAL to champion (0.888) on all 3 runs. Why: extract_all_variants' offline ceiling on dev gold is 80/90 = 0.889 — the regex tops out exactly where the model already was, and what it misses is structural (wild-type <GENE>*1 alleles the paper never writes; under-enumerated HLA). Agent was strictly MORE PRECISE (201 keys vs 225, 246 sentences vs 278, every dropped key spurious) but eval.py scores recall only and doesn't penalize extras, so precision is invisible and shows up as cost: $6.3/run and 12 min vs $0.02 and 56s. LESSON: compute a recall tool's offline ceiling against gold before building it (free); a verification tool can't pay for itself under a recall-only metric. Only real gain: variance collapsed to sd 0.008 (vs jun5's 0.062 spread) because the schema-enforced submit_annotations tool replaced prose JSON parsing.
failure-analysis (val, per-gold-sentence judge) — CORRECTS the agentic lesson above. Regex-alone ceiling on VAL is 83/89=0.933, not the 0.889 I measured on dev; and `agent_prediction UNION regex_candidates` = 85/89 = 0.955. The tool was never the bottleneck — trust in the tool was. Where the score really goes (101 gold sentences): OK 42, QUALIFIER_DROPPED 30, SENTENCE_LOST 18, MISSING_VARIANT 11 — extraction is the SMALLEST bucket and every jul9 tool targeted it. Also: regex_variants.normalize_star_allele() strips the xN suffix and would destroy the very keys (a) recovers. Report: analysis/failure_analysis.html.
