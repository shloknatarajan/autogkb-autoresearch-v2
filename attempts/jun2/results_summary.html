What worked / what didn't

✓ What worked

  • Two same-model passes (exhaustive + “find what the first reader missed”). Single pass dropped to 0.573 (iter8); the 2nd pass adds genuine recall.
  • Deterministic cross-filing — file each sentence under every allele it names. Gold keys a *3/*3 vs *1/*1 sentence under *1, *3 and *4; since meaning_capture is macro-per-variant, populating those keys is a direct win (iter4, +cross-filing).
  • Wild-type→*1 mapping (iter6, the big jump 0.578→0.674). The model writes “UGT1A1 wild-type”; gold uses UGT1A1*1. Minting the *1 key recovered whole zero-capture variants.
  • Capping candidates/variant (iter13). Trimming the long non-matching tail let the judge find the one true match it was losing in the noise.
  • Doing it all in post-processing, not the prompt — deterministic, free, and it never perturbs the sentences that already match.

✗ What didn't

  • Prompt rephrasing (iter5, forcing *1). Changing instructions perturbed the wording of sentences that already matched → net −0.05. Post-processing is safer than prompt surgery.
  • Adding a 3rd reader (iter7) and a Claude diversity pass (iter10). Both raised variant_coverage but lowered capture: differently-worded sentences for the same association flood each variant’s list and dilute the LLM judge.
  • rsID↔star equivalence filing (iter9): copying sentences onto already-answered keys diluted them.
  • Protecting populated keys (iter11): the opposite also failed — exact cross-filing into populated keys helps, because it carries the right sentence into a key the model filed under a different allele.

The core finding: the LLM judge is dilution-sensitive

Every regression shares one mechanism. The judge does a one-to-one match of predicted↔gold sentences per variant. Gold has at most 3 sentences per variant (mean 1.17, median 1); the pipeline emits 60–166+. The recall-max strategy (“emit every framing, extras are free”) assumed extras are harmless, but they are implicitly penalized: a longer candidate list makes the judge more likely to miss the single correct-direction / correct-comparison sentence buried among plausible-but-wrong reciprocals. So exact, correctly-keyed cross-filing helps; reworded volume hurts.

✓ Success — reference-allele recovery (iter6)

PMC10946077, UGT1A1*1 — went from 0/3 captured (pred had 0 sentences) to captured, purely from the wild-type→*1 rule.

Cross-filing minted the UGT1A1*1 key → the gold variant is now scored.

✗ Failure — functional & over-generation

PMC10786722, rs56038477 — 0/1 captured though the model emitted 7 sentences for it: none asserted the functional meaning.

      as compared to genotype CC.
MISS: model produced dose/toxicity sentences, never the enzyme-activity one.

Over-generation, PMC6714829: 2 gold-relevant variants, 326 predicted sentences (166 + 160). The right sentence exists somewhere in 166 candidates; the judge can’t reliably pick it.

Do we need to update the eval?

Not the contract (the split, scoring, and judge prompt should stay frozen so scores remain comparable) — but the run surfaced three issues worth addressing in a future revision:

1. Data-loading fragility (already fixed at source)

load_bench() uses read_text().splitlines(), which splits on all Unicode line-breaks (\x0b \x0c \x85  …). A supplement-refresh had embedded such characters inside markdown_content, so 26 of 32 records failed to parse and eval crashed. Fixed by re-encoding the bench with ensure_ascii=True (gold byte-identical) and hardening tools/refresh_bench_supplements.py to sanitize fetched text. Optional hardening: have load_bench split on "\n" only, so malformed input can never silently shard a record.

2. Judge stochasticity dominates small deltas  (highest priority)

The same generations re-scored give ±0.02–0.025 on meaning_capture. With 16 papers and a macro average, that swamps any change smaller than ~0.03, so keep/discard on single draws is unreliable. Recommend: score each generation set with N≥3 judge runs and report mean ± sd (or a seeded/deterministic judge). This is the single most valuable eval upgrade.

3. “Extra sentences are not penalized” isn’t true in practice

The spec says spurious predictions are free, and structurally they are — but the LLM judge’s accuracy degrades as the predicted list grows, so volume is penalized implicitly and inconsistently. This rewards gaming-by-omission (a pipeline that emits fewer, cleaner sentences can outscore a more complete one). Options: (a) judge each gold sentence independently against the full predicted set (removes the one-to-one ordering/dilution artifact); (b) cap predicted sentences per variant inside eval so all pipelines are compared at equal list length; or (c) add an explicit precision term so the trade-off is visible rather than hidden in judge noise.

What I’d try next

The data says the lever is precision, not volume: gold wants ~1–3 sentences/variant, stated in the paper’s own direction. Drop the reciprocal + every-genotype explosion (iter2’s tactics, which predate cross-filing) and emit each association once; add a dedicated functional-association reader for the “activity of GENE” misses. Both aim to put the one correct sentence at the front instead of burying it.
